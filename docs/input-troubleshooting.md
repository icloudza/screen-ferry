# 键鼠与 Windows 安全输入验证

自动化测试使用真实 TLS、本机通信和模拟平台；Windows 焦点、UAC、锁屏、安装器和游戏仍需实机验收。
**安全输入服务随正式安装包提供，安装时默认不选；Windows 实机验收按本文的清单逐项记录。**

2026-11-03 已在 macOS arm64 执行：workspace 格式、Clippy、测试、结构 lint 和依赖检查；
Windows GNU 目标的 Clippy，以及服务与后台的交叉编译、链接；
代理协议、签署正文和授权码解析使用有效种子完成 100,000 次模糊测试，未发现崩溃；
纯逻辑和真实 TLS 场景覆盖篡改、重放、挑战轮换与撤销。
本地交叉检查和 CI 通过不代表 Windows 功能已验收。
数据连接故意停在 TLS 握手的真实连接场景已通过：输入及签署保活继续，租约不因等待数据通道而到期。

计算基准：`cargo bench -p ferry-trust --bench input_proof`，Apple M4 Max、macOS arm64、release 构建，
预热 256 次后测 20,000 条证明，单次签名平均 10.37 µs、验证平均 26.48 µs。
这只包括证明的计算成本，不包括编码、TLS、本机管道、策略查询或 Windows 注入；不能当作端到端延迟。

## 已验证的普通输入逻辑

- 设备的边缘停留时间同时用于进入和返回，移离切换边缘、按下/松开鼠标键或改变布局后重新计时。
- Ctrl + Option（Windows 为 Alt）+ Esc 及断线立即归还控制，不等停留时间。
- 注入失败时结束会话；只有成功注入才更新按键状态。释放失败的键保留到恢复后重试。
- 两端设置界面都关闭后仍能控制、输入和切换，已有真实 TLS + IPC 场景测试。
- 没有安全输入服务时，Windows 遇到无法操作的管理员窗口或安全桌面，会请控制端收回光标并记录原因；连接保持，剪贴板和文件照常，恢复后再把光标推过来。

## 构建与安装

```text
cargo xtask bundle
```

无需 Flutter 的命令行验收包可用 `cargo xtask input-validation` 生成；交叉构建时传 `--target x86_64-pc-windows-gnu`。
Windows 手工操作步骤见 [验收说明](windows-secure-input-validation.md)，其中的测试结果由实际运行者逐项记录。

安装器提供“允许已配对的电脑操作 Windows 权限提示（UAC）”，默认不选。没选、也从没装过服务时，安装过程不运行服务程序。
选了这一项时，安装目录必须是本机受保护的 `ScreenFerry` 目录，建议使用默认 Program Files。
安装包先用自身临时解出的工具验证目录，再复制文件；不从用户可写的目标目录运行旧工具。
升级先停止代理和服务，保留之前的安装任务选择；卸载移除服务并保留用户配置和配对记录。

普通后台保持网络、配对、剪贴板和文件处理；SYSTEM 服务只管理当前控制台会话中的输入代理。代理不会读取配置路径或运行外部命令。
每个桌面有独立线程，桌面切换时保留网络连接。源码入口见 ADR 0015。

## 独立授予及撤销 UAC 权限

普通配对不会授予 UAC 控制权限。先完成配对，再按以下步骤操作：

1. 在控制端运行 `screenferry input-key`；使用自定义数据目录时带相同的 `--data-dir`。输出只包含证书指纹和公开 P-256 公钥，没有私钥。
2. 通过可信渠道核对控制端输出。不要直接相信被控端普通后台、配对文件或聊天中来历不明的授权码。
3. 在被控 Windows 的普通用户终端运行 `whoami /user`，记下实际运行后台的用户 SID；使用其他管理员账户批准 UAC 时也授权这个用户 SID。
4. 在被控端管理员终端运行 `screenferry-service authorize <用户SID> <控制端公开授权码>`，之后让后台重新连接，以重新协商安全输入能力。
5. 撤销使用 `screenferry-service revoke <用户SID> <完整设备指纹>`。代理每次输入及空闲检查都重查策略，当前会话也会结束。取消安装任务或卸载会清除机器级授权，保留普通用户的配对记录。

策略固定保存在 64 位 `HKLM\Software\ScreenFerry\SecureInput`，以 `用户SID.完整设备指纹` 为值名，值是 65 字节公开公钥。
SYSTEM/管理员可写，普通用户只读；代理核验各级 owner、ACL 并拒绝注册表链接。不从用户配置导入授权，不接受远端注册表路径。
如曾手动删除服务登记，应先从可信安装目录运行管理员命令 `screenferry-service remove`，再卸载，以一并清除策略。
重新安装且不选择安全输入时，安装包中的可信新工具也会清除旧策略；卸载器不会从任意用户可写目录启动额外的特权清理工具。

代理独立验签完整动作，验证有时限的代理随机挑战和连续序号。只有签署输入/保活续期远端租约，本机健康检查不能续期；
未签署、篡改、重放、过期或未进入屏幕的特权输入均关闭管道并清理。完整进入/退出、锁定键、定位后点击及光标操作都在代理中执行。
签署输入按能力协商，和旧版本照常互连。实现和威胁边界见 ADR 0016。

**仍未通过生产验收：** 签署动作正文在普通后台中仍可见，来源认证不提供防本机后台读取输入的端到端保密能力。
不得据此宣称已抵御全部同账户恶意程序威胁；生产开放前还需评估凭据输入的保密边界、安全复查及 Windows 实机验收。

| 仅普通配对、没有管理员 UAC 授权 | 普通权限共享可用，安全桌面输入拒绝，修改 peers.toml 不能提升权限 |
| 策略可写 ACL、注册表链接、其他用户 SID、错误公钥 | 拒绝安全输入，不能绕过独立授权 |
| 控制中执行 revoke、取消功能、卸载后重装 | 当前权限及时失效，停用/卸载后不残留机器级授权，重新启用需重新授权 |
| 本机 Check 持续发送但远端没有签署保活 | 远端租约仍到期，释放输入状态 |
| 锁屏后解锁，Default/Winlogon 往返 100 次 | 无残留修饰键/鼠标拖动，无持续增长的工作线程或句柄 |
| 按住 Shift、Ctrl、鼠标键时出现 UAC，随后松开 | 旧桌面无法立即释放的键在恢复时补发；新桌面不继承旧的卡键 |
| 停止普通后台、断网、结束代理、停止服务 | 及时归还控制并恢复光标；健康代理在租约过期后释放已注入的键 |
| 注销后同一账户重新登录、切换用户 | 不沿用旧登录身份；按会话号、用户 SID 和 AuthenticationId 重建代理 |
| 伪造同名管道、其他映像连接管道、非当前会话连接 | 双向验证拒绝；不能通过名称抢占获得输入权限 |
| 重放序号、过期请求、半帧、客户端不读取回复 | 关闭连接，不重放输入，不无限等待；无未完成 I/O 使用已释放缓冲区 |
| 选择用户可写目录、重解析路径或含可写根文件的安装目录 | 启用前拒绝，不执行目标目录中的程序 |
| 启用后的升级、禁用、卸载、重启 Windows | 不残留代理进程或服务；禁用/卸载后普通输入可继续使用 |

## 日志对齐

比较同一时间段的 `输入转发统计.sent_inputs` 与 `输入注入统计.applied_inputs`（每 5 秒汇总，两个窗口不完全对齐）。
`slowest_injection_ms` 是单次平台调用的最长耗时。数量相近不能证明目标程序实际接受了输入，需要结合真实光标、前台窗口和权限状态。
统计不含具体按键或剪贴板内容。若统计停止，结合心跳、断线及进程状态判断阻塞位置。

## 明确不包含的范围

本次代理针对 Windows 被控端；Windows 控制端的安全桌面捕获、首次登录前、RDP、多用户同时共享和 Ctrl+Alt+Del/SAS 不包含在内。
游戏键盘问题单独比较普通程序、管理员程序、窗口和全屏模式，不能仅凭现象认定反作弊，也不承诺提升权限就能解决。
