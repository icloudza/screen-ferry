# 0015 Windows 安全桌面输入服务

状态：已采纳（维护者要求实现 UAC 控制）

实施状态：服务与桌面代理已实现，并按 ADR 0016 补充了独立的远端输入认证。2026-11-10 维护者决定随正式安装包开放：安装时可选、默认不选。Windows 实机验收按 `docs/input-troubleshooting.md` 的清单进行。

## 背景

普通用户进程不能注入 UAC 安全桌面。仅在失败时断开连接能够避免失控，但不能远程确认 UAC。
把整个后台放进 SYSTEM 也能做到，但高权限里就有了网络、剪贴板和文件。本项目采用独立输入代理，缩小高权限进程的职责。

## 决定

- 创建规范中预留的 L4 `ferry-service`，生成 `screenferry-service`。不改变目录、依赖层级或现有设置界面 IPC。
- Windows 安装器提供明确的可选任务：允许已配对设备操作 Windows 权限提示。默认不选，升级不自动增加权限。
  便携版保持普通权限行为；不修改 UAC、签名策略或现有配置字段。
- Windows 服务以 LocalSystem 运行，只在已登录的当前控制台会话启动同一个固定服务程序的输入代理模式。
  从自己的令牌创建会话令牌，不读取其他进程的令牌。固定应用路径、固定参数，不继承句柄；代理核验父服务后只复制停止事件的等待权限，避免跨会话继承。
- 代理放入关闭即结束的 Job；服务正常停止先通知代理清理，超时再终止。用户会话变化时终止旧代理。
- Job 只允许一个进程，代理不能启动子进程。代理在取得登录用户后永久移除除目录遍历外的令牌特权。
  服务自身保留创建会话进程所需特权；不把整个网络核心放入 SYSTEM。
- 网络、身份和配对、设置界面、剪贴板、文件和磁盘历史继续在普通用户后台，不进入服务或代理。
- 代理只提供输入、锁定键同步、光标显示和保活。不存在运行命令、传入文件路径、读写文件或修改配置的请求。
- 代理的本机命名管道按会话区分，拒绝远程客户端，只允许 SYSTEM 和对应登录用户；一实例，不在连接之间释放管道名。
  双向使用 Windows 提供的管道对端 PID 检查进程令牌和会话。后台核验代理是 SYSTEM，并且就是 SCM 登记的那个服务程序；
  代理核验客户端是同一登录会话里的同一个用户。客户端禁止服务端冒充自身。
  这里是内部权限边界，Flutter 的回环 TCP + 令牌协议保持不变。
- 服务程序固定放在系统盘的 `Program Files\ScreenFerry`，和 ScreenFerry 自己装在哪个盘无关（装在默认位置时两者是同一个目录）。
  这个目录、它的所有上级和目录里的文件必须由 SYSTEM/管理员拥有且没有其他主体的写权限；拒绝重解析路径。
  其他盘的目录通常做不到这一点（根目录默认允许登录用户写入），所以不把服务程序放在用户选的位置。
  后台从 SCM 的登记得到服务程序的位置，登记只有管理员能改。
- 代理不核对客户端是哪个程序：后台可以装在不受保护的位置，核对它的路径没有意义；同一用户的其他程序本来也能操纵后台。
  特权输入的把关不在这里，而在远端设备签名和管理员授权（ADR 0016）：没有授权设备的签名，连上管道也只能查询状态和松开按键。
- 内部协议独立编号，定长、严格解析、不接受额外字段；每条请求具有连续序号和系统单调时钟的到期时间。
  超时立即关闭连接，不在失败后重放输入。只有重新验证的新连接才能继续。
- 管道使用 overlapped I/O 与完成事件，不依赖 Sleep 轮询；取消后确认 I/O 已完成再释放缓冲区。
- 每个输入桌面使用独立线程，在线程创建窗口之前调用 `SetThreadDesktop`。按当前输入桌面路由；桌面变化不重启网络引擎。
  桌面名称限定为 Default 和 Winlogon，不为任意桌面建立线程。
- 代理跟踪自己成功注入的按键。换桌面时释放旧桌面上的键；无法释放的保留到该桌面重新可用。断联、保活超时、会话切换
  和正常停止时释放按键并恢复光标。工作线程无响应则代理失败退出，由服务重建，普通后台归还控制。
- Windows API 和 unsafe 都放在 `ferry-platform-windows/src/inject/` 下；L4 只解析参数、组织运行和报告错误。
  定长协议在 L1 `ferry-proto`，序号与租约判断在 L1 `ferry-core`，用公开接口做跨平台测试。

## 范围与验证

### 发布前的输入来源边界

固定映像、SID、会话和 ACL 校验能拒绝其他可执行文件及其他账户，不能证明普通后台没有被同账户程序操纵。
后台使用的配对配置归用户所有，同账户程序也可能启动真正的后台并提供另一份配置。因此不能把“进程名称/路径合法”
等同于“输入一定来自管理员已授权的远端”，也不能宣称本版本已隔离同账户恶意程序。

ADR 0016 采用管理员单独授权、公钥验签、代理随机挑战和签署保活，补齐来源认证代码与自动化场景测试。
普通后台不能直接提交原始特权键鼠请求。服务随正式安装包提供，安装时默认不选；没有管理员单独授权的设备用不了这条通道。
当前动作正文在普通后台中仍可见；来源认证不提供防本机后台读取远端输入的端到端保密能力，
不能宣称已经抵御所有同账户恶意程序威胁。

### 系统范围

支持已经登录的控制台会话中的 UAC 和锁屏；首次登录前、RDP、多用户同时共享及 Ctrl+Alt+Del/SAS 不在这一版范围内。
这次实现针对 Windows 被控端；Windows 控制端在安全桌面上的输入捕获不在本次范围。
安装、升级、卸载、冒充管道、未授权进程、半帧、过期请求、断联释放及 Default/Winlogon 往返列入 Windows 实机验证。
交叉编译不能替代这些实机检查，不仅凭单元测试宣称 UAC 已验证。
